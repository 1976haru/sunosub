# HTTP 상태 코드 정리 — 대기 목록

작성일: 2026-08-17 (최종 테스트 끝난 뒤 한 번에 진행하기로 함 — 지금은 건드리지 않음)

## 배경

`tools/social-studio/parse/setPackLoader.js`의 `SetPackValidationError`가 `status`를
세팅하지 않아 사용자 입력 오류(가사 JSON 형식 오류 등)가 500으로 나가던 버그를 고치면서
(`cb41e41`), 다른 도구들도 스캔했다. `server.js`의 공용 에러 미들웨어는
`error.status`(기본값 500)만 보고 HTTP 상태를 정하므로, `throw new Error(...)`에
`status`를 안 붙이면 전부 500으로 뭉뚱그려진다 — 보안 검증 실패든 사용자 입력 누락이든
서버가 실제로 고장난 것과 로그에서 구분이 안 된다.

`routes/shorts.js`의 경로 탈출 검증(`resolveFileUrl`)이 이 이유로 500에 묻혀 있어서
그 한 건만 먼저 400으로 고쳤다(아래 표에 완료로 표시). **나머지는 아래 목록으로만
정리해두고, 최종 테스트가 끝난 뒤 한 번에 진행한다** — 지금 20여 곳을 한꺼번에 건드리면
테스트 중 문제가 났을 때 원인이 이 변경 때문인지 다른 이유인지 구분하기 어려워진다.

## 이미 올바르게 되어 있는 참고 사례

- `routes/timeline.js`: `httpError(message, status = 400)` 헬퍼. AI 응답 파싱 실패는
  이미 **502**로 구분되어 있다(`throw httpError('AI 응답 형식이 올바르지 않습니다.', 502);`,
  `routes/timeline.js:220`).
- `tools/social-studio/server/packRoutes.js`: 동일한 `httpError` 패턴 + 자체 라우터
  에러 미들웨어에서 `PackStateError`를 400으로 특별 처리.

**나중에 고칠 때 이 패턴을 그대로 따른다**: 각 파일 상단에
`function httpError(message, status = 400) { return Object.assign(new Error(message), { status }); }`
를 추가하고, `throw new Error(...)`를 `throw httpError(...)`로 바꾼다. 사용자 입력
누락/형식 오류는 기본값 400 그대로 두고, "AI가 아무것도 안 줬다/이상한 걸 줬다" 계열만
`httpError(message, 502)`로 명시한다(timeline.js의 기존 관례).

## 진행 안 한 것 (참고용으로 확인만 함, 손대지 않음)

`tools/social-studio` 내부 커스텀 에러 클래스도 같이 훑었다. 대부분 지금 그대로가 맞다:

- `HistoryCorruptError` (`store/history.js`) — 로컬 `history.json` 파일 손상. 진짜
  서버 쪽 데이터 문제라 500이 맞다.
- `MissingFontError` (`generate/cards.js`) — 번들 폰트 파일이 배포에서 빠진 것. 관리자가
  고칠 문제라 500이 맞다.
- `HatenaHttpError` (`publish/hatenaClient.js`) — 이미 자체적으로 `status`를 세팅한다.
- `TemplatePoolError` (`generate/slotFiller.js`) — 대부분 상위(`blogPost.js`)에서
  캐치되어 사용자에게 노출조차 안 되지만, `generate/youtubeSet.js`는 캐치 없이 호출한다.
  업로드한 가사 JSON의 `channelId`에 아직 템플릿이 없다는 뜻이라 400에 가까운데,
  "관리자가 템플릿을 더 써야 한다"는 성격도 있어 애매하다 — 나중에 고칠 때 판단 필요.
