## 0. 이 문서를 쓰는 방법

**지시문 1개 = Claude Code 대화 1개.** 여러 개를 한 번에 던지지 않습니다. 컨텍스트가 섞이면
Claude Code가 앞 작업을 되돌리거나 절반만 하고 "완료했습니다"라고 보고하는 일이 실제로 생깁니다.

한 지시문의 사이클은 항상 이렇습니다:

```
1. 지시문 복사 → Claude Code에 붙여넣기
2. Claude Code가 구현 + 자체 검증
3. ★ 실제 출력 샘플을 받아서 내 눈으로 확인 ★
4. 문제 없으면 커밋 → 다음 지시문
```

3번을 건너뛰지 않습니다. 이 프로젝트에서 이미 두 번 겪은 일입니다:

> **테스트 통과 ≠ 품질.** 장르 차별화 버그는 470개 테스트를 전부 통과한 상태에서
> Suno로 실제 생성해 보고서야 발견됐습니다. 타임라인 연번 버그도 "화면에는 번호가
> 붙는데 실제 파일명은 그대로"였고, 테스트는 화면 문자열만 봤기 때문에 통과했습니다.

그래서 아래 모든 지시문의 **완료 기준에는 "실제 출력 샘플을 보고하라"가 들어 있습니다.**
테스트 개수만 보고하는 응답은 완료로 치지 않습니다.

## 지시문 #02 — `CLAUDE.md` 작성

> **작업: 이 저장소 루트에 `CLAUDE.md`를 만들어라.**
>
> 앞으로 모든 Claude Code 작업이 이 파일을 먼저 읽게 된다. 지켜야 할 규칙을 담는다.
> 저장소 코드를 실제로 읽어보고 쓸 것. 추측으로 채우지 마라.
>
> **포함할 내용:**
>
> 1. **프로젝트 개요** — 로컬 전용 Express 서버(포트 5300) 하나가 5개 도구를 iframe으로
>    서빙한다. 시니어 대상 유튜브 플레이리스트 채널 2개(한국 아침 / 일본 쇼와 카페)의
>    제작 파이프라인 도구다.
>
> 2. **실행/검증 명령** — `npm start`, `npm run dev`, `npm run check`. 각각 뭘 하는지.
>
> 3. **아키텍처 제약 (어기면 안 되는 것)**
>    - `tools/*/`는 **빌드 스텝이 없는 정적 파일**이다. `tools/timeline/index.html`은
>      HTML+CSS+JS가 한 파일에 들어있는 단일 파일이고, 여기에 import/모듈 시스템을
>      도입하지 마라. `tools/yt/app.js`만 `type="module"`이다.
>    - `tools/storyboard/`는 `storyboard-app/`의 vite 빌드 산출물이다. **직접 수정 금지**,
>      `storyboard-app/` 소스를 고치고 다시 빌드해야 한다.
>    - `stripLeadingNumber()`가 `routes/timeline.js`와 `tools/timeline/index.html`에
>      의도적으로 중복돼 있다. 정적 페이지와 서버가 모듈을 공유할 수 없기 때문이다.
>      **한쪽을 고치면 반드시 다른 쪽도 같이 고쳐라.** 두 정규식은 바이트 단위로 같아야 한다.
>    - Gemini 키는 `lib/keyStore.js`를 통해서만 읽는다. 키 값을 응답이나 로그에 절대
>      노출하지 마라.
>
> 4. **파일 시스템/외부 쓰기 규칙 (안전장치)**
>    - 사용자 폴더의 파일명을 바꾸는 코드(`routes/timeline.js`)는 확장자 화이트리스트,
>      시스템 폴더 차단, 자기 자신 폴더 차단, 이름 충돌 감지, 백업 파일 기록을 전부
>      서버가 재검증한다. 클라이언트 미리보기를 신뢰해서 건너뛰지 마라.
>    - `videos.update`는 지정한 part를 **통째로 교체**한다. 값이 있는 속성을 빼고 보내면
>      삭제된다. 그래서 등록 경로는 항상 `videos.list` → 기존 값 보존 → 병합 → `PUT`의
>      read-modify-write다. **이 패턴을 절대 단순화하지 마라.**
>    - 외부에 쓰는 기능은 전부 **미리보기(dryRun) → 적용** 2단계다. 적용은 미리본 계획
>      그대로만 전송한다. 새 기능을 추가할 때도 이 패턴을 따라라.
>
> 5. **비밀 정보** — `.gemini_key`, `.yt_oauth.json`은 gitignore 대상이며 절대 커밋하지
>    않는다. 코드 예시나 문서에 실제 키/토큰 값을 적지 마라.
>
> 6. **작업 보고 규칙 (가장 중요)**
>    - 작업을 끝냈다고 보고할 때 **테스트 통과 개수만 말하지 마라.**
>    - 반드시 **실제 생성된 출력 샘플**(타임라인 텍스트 3줄, API 응답 JSON, 번역 결과 등)을
>      붙여서 보고해라.
>    - 실행해 보지 않고 "동작할 것입니다"라고 쓰지 마라. 실행할 수 없는 이유가 있으면
>      그 이유를 명시해라.
>    - 커밋 메시지는 기존 형식을 따른다: `feat: 영문 요약 (CS-vX.Y)` + 본문에 이유.
>
> 7. **버전 규칙** — 기능 변경 시 `CS-v1.7`, `CS-v1.8`... 로 올린다. 코드 주석에
>    `TASK CS-vX.Y` 형태로 "왜 이렇게 했는지"를 남기는 것이 이 저장소의 관행이다.
>    기존 주석 스타일을 `routes/timeline.js`와 `lib/ytOAuth.js`에서 확인하고 따라라.
>
> **완료 기준:** `CLAUDE.md` 전문을 나에게 보여주고, 위 3번의 아키텍처 제약이 실제
> 코드와 일치하는지 각 항목마다 해당 파일·줄을 근거로 확인했다고 보고해라.

## 지시문 #03 — CS-v1.6 실전 검증

> **작업: 유튜브 번역 자동 등록 기능을 실제 채널에서 검증하고, 발견된 문제를 고쳐라.**
>
> 이 기능은 코드는 있지만 실제 유튜브 계정에 한 번도 써본 적이 없다. 실제로 돌려보고
> 깨지는 곳을 찾는 것이 이 작업의 목적이다.
>
> **먼저 나에게 안내해라 (내가 손으로 해야 하는 부분):**
> Google Cloud OAuth 클라이언트를 만드는 절차를 이 저장소의
> `tools/yt/index.html` 설정 안내와 대조해, 실제 콘솔 화면 기준으로 빠진 단계가 없는지
> 확인하고 나에게 정리해서 알려줘라. 특히 다음을 확인해라:
> - YouTube Data API v3 사용 설정 위치
> - OAuth 동의 화면 "외부" + 테스트 사용자 추가
> - 웹 애플리케이션 클라이언트 + 승인된 리디렉션 URI
> - 요청 범위(scope)가 `youtube.force-ssl` 하나로 충분한지
>
> **내가 연결을 마치면 아래를 순서대로 검증한다. 각 단계의 실제 응답을 보여줘라.**
>
> 1. `GET /api/yt/oauth/status` — `connected: true`, 채널 이름이 맞게 나오는가
> 2. `GET /api/yt/my-videos` — 내 영상 목록이 실제로 나오는가
> 3. `POST /api/yt/publish-localizations` (`dryRun: true`) — **비공개 테스트 영상 1개**로
>    미리보기. 언어 코드 매핑 결과 전체를 보여줘라. `ko`, `ja`, `en-US`, `es-419`,
>    `pt-BR`이 각각 어떤 코드로 해석되는지 확인한다.
> 4. `i18nLanguages.list`가 실제로 응답하는지, 지원 목록에 위 코드들이 있는지 확인해라.
>    (`lib/ytLanguages.js`의 후보 배열이 현실과 맞는지 검증하는 단계다)
> 5. 실제 등록(`dryRun: false`) 후 `GET /api/yt/localizations`로 다시 읽어서
>    **올린 값과 유튜브에 저장된 값이 일치하는지** 대조해라.
> 6. 유튜브 스튜디오 화면에서도 보이는지 내가 확인할 수 있게 어디를 봐야 하는지 알려줘라.
>
> **특별히 의심하고 확인할 것 (실패 가능성이 높은 지점):**
> - `snippet.defaultLanguage`를 새로 설정할 때 **기존 제목/설명이 지워지지 않는가.**
>   등록 전후의 `snippet.title`, `snippet.description`, `snippet.tags`, `categoryId`를
>   전부 대조해서 바이트 단위로 같은지 확인해라. 하나라도 달라지면 심각한 버그다.
> - 설명란에 타임라인(`00:00 01. ...`)이 들어있는 긴 설명(2,000자 이상)도 정상 등록되는가
> - 제목이 100자를 넘는 언어(독일어 등)에서 잘림 처리가 맞는가
> - OAuth 팝업이 Creator Studio 셸의 iframe 안에서 정상 동작하는가
>
> **완료 기준:** 위 6단계의 실제 응답 로그 + 등록 전후 snippet 대조 결과를 보고하고,
> 발견된 버그가 있으면 고친 뒤 `fix: ... (CS-v1.6.1)` 로 커밋해라.
> 버그가 없으면 "없음"이라고 명시적으로 보고해라.

## 지시문 #04 — 채널 프로필

> **작업: 채널별 프리셋을 만들어 매번 같은 설정을 다시 고르지 않게 한다. (CS-v1.7)**
>
> 채널이 2개인데 도구는 채널 개념이 없다. 그래서 매번 번역 언어 50개 중 고르고, 원문
> 언어를 고르고, 해시태그를 손으로 붙인다.
>
> **신규 파일 `lib/channelProfiles.js`** 를 만들고 기본 프로필 2개를 정의해라:
>
> ```
> korean-morning:
>   label: "한국 아침 플레이리스트"
>   sourceLanguage: ko
>   bracketMode: ja          (타임라인 괄호 제목 기본값)
>   targetLanguages: [일본어, 영어 (미국), 베트남어, 인도네시아어, 태국어, (중국어 계열 — 위 검토 결과에 따라)]
>   descriptionTemplate / hashtagTemplate
>
> japanese-showa-cafe:
>   label: "일본 쇼와 카페"
>   sourceLanguage: ja
>   bracketMode: ko
>   targetLanguages: [한국어(신규 추가 필요), 영어 (미국), 태국어, 베트남어, (중국어 계열 — 위 검토 결과에 따라)]
>   descriptionTemplate / hashtagTemplate
> ```
>
> **★ 먼저 해결해야 할 문제 (이미 확인된 사실) ★**
> `tools/yt/app.js`의 `LANGUAGES` 배열에는 **`'한국어'`가 없다.** 원문이 한국어라는
> 전제로 만들어진 목록이기 때문이다. 그런데 일본 쇼와 카페 채널은 원문이 일본어이고
> **한국어가 번역 대상**이어야 한다. 지금 구조로는 일본 채널이 한국어 번역을 못 만든다.
>
> 그래서 #04의 첫 작업은 이것이다:
> - `LANGUAGES` 배열에 `'한국어'`를 추가해라. (`lib/ytLanguages.js`에는 `'한국어': ['ko']`가
>   이미 있으니 매핑은 손댈 필요 없다)
> - 원문 언어와 같은 언어가 번역 대상으로 선택되면 UI에서 회색 처리하거나 경고해라.
>   한국어 원문 → 한국어 번역은 무의미하다.
> - `CORE_LANGUAGES` 프리셋도 채널에 따라 달라져야 하는지 검토해라.
>
> **중국어 계열도 확인 필요:** 현재 목록에는 `'광둥어 (홍콩)'`, `'중국어 (싱가포르)'`
> 둘뿐이고 **대만 번체(`zh-TW`)와 중국 간체(`zh-CN`)가 없다.** 시니어 플레이리스트
> 시청층에서 대만·홍콩 비중을 고려하면 `'중국어 (대만)'`, `'중국어 (중국)'`을 추가하는
> 게 맞는지 나에게 의견을 물어보고 결정해라. 추가한다면 `lib/ytLanguages.js`의
> 후보 배열에도 항목을 같이 넣어야 한다.
>
> `targetLanguages`의 라벨은 **반드시 `tools/yt/app.js`의 `LANGUAGES` 배열과 정확히
> 일치하는 문자열**을 써라. 하나라도 다르면 `lib/ytLanguages.js`가 코드를 못 찾는다.
> 코드를 읽어서 실제 라벨을 확인하고 쓸 것. 추측 금지.
>
> **템플릿 변수**는 `{{title}}`, `{{trackCount}}`, `{{timeline}}`, `{{channelName}}`
> 정도로 최소한만 지원해라. 템플릿 엔진을 새로 만들지 마라 — 단순 치환이면 충분하다.
>
> **엔드포인트:** `GET /api/profiles`, `POST /api/profiles` (사용자 수정본 저장).
> 저장 위치는 `.channel-profiles.json` (gitignore 추가). 기본 프로필은 코드에 두고,
> 사용자가 수정하면 파일이 덮어쓴다.
>
> **UI:** 유튜브 도구와 타임라인 도구 상단에 채널 선택 드롭다운 하나씩. 선택하면
> 해당 도구의 기본값이 채워진다. **선택 후에도 개별 항목을 손으로 바꿀 수 있어야 한다**
> (프리셋이 사용자를 가두면 안 된다).
>
> **하지 말 것:** 기존 동작을 바꾸지 마라. 채널을 안 고르면 지금과 똑같이 동작해야 한다.
>
> **완료 기준:** 두 프로필을 각각 선택했을 때 실제로 채워지는 값(언어 목록, 괄호 제목
> 모드, 조립된 설명란 텍스트)을 출력해서 보여줘라.

## 지시문 #05 — 업로드 패키지 (타임라인 → 설명란 자동 조립)

> **작업: 타임라인 도구가 "유튜브 설명란 완성본"을 통째로 만들게 한다. (CS-v1.7)**
>
> 지금 타임라인 도구는 `00:00 01. 제목` 목록만 만든다. 실제 설명란에는 그 위에 채널
> 소개문, 아래에 해시태그·저작권 문구가 붙는다. 그걸 매번 손으로 붙이고 있다.
>
> 타임라인 도구 출력 패널에 **"설명란 완성본" 탭**을 추가해라. 기존 "타임라인만" 출력은
> 그대로 두고 탭으로 전환한다.
>
> 조립 순서: `인트로 문구` → `타임라인` → `아웃트로/저작권` → `해시태그`
>
> - 문구는 #04의 채널 프로필 템플릿에서 가져온다. 프로필이 없으면 편집 가능한 기본
>   텍스트를 쓴다.
> - **AI 음악 고지 문구**를 아웃트로 기본값에 넣어라 (Suno로 생성한 음원임을 명시).
>   문구 초안은 네가 제안하고 내가 확정한다.
> - 유튜브 설명란 상한이 5,000자다. 조립 결과 길이를 실시간으로 보여주고 넘으면 경고해라.
> - **첫 타임스탬프가 `00:00`이어야 유튜브가 챕터로 인식한다.** 시작 시간이 `00:00`이
>   아니면 "챕터로 인식되지 않습니다" 경고를 띄워라. 챕터 인식 조건(최소 3개, 각 10초
>   이상, 오름차순)도 검사해서 알려줘라.
>
> **완료 기준:** 12곡짜리 실제 타임라인으로 조립한 설명란 전문을 출력해서 보여주고,
> 글자 수와 챕터 인식 조건 검사 결과를 함께 보고해라.

## 지시문 #06 — 도구 간 데이터 전달

> **작업: 타임라인 결과를 번역기로 한 번에 넘긴다. (CS-v1.7)**
>
> 지금은 타임라인에서 만든 설명란을 복사 → 탭 이동 → 번역기 입력란에 붙여넣기를 손으로
> 한다. 이걸 버튼 하나로 만든다.
>
> - 타임라인 도구에 **"번역기로 보내기"** 버튼 추가.
> - 도구들은 iframe으로 격리돼 있으므로 `public/shell.js`에 **`postMessage` 중계**를
>   구현해라. iframe → 셸 → 대상 iframe. 셸이 중계자다.
> - 받는 쪽(번역기)은 원문 제목/설명 입력란을 채우고 해당 탭으로 자동 전환한다.
> - **덮어쓰기 전에 확인을 받아라.** 번역기에 이미 작업 중인 내용이 있으면 그냥 날리면 안 된다.
> - `postMessage`의 `origin`을 검증해라 (같은 출처만 허용).
>
> **번역기의 타임라인 보호 확인:** `routes/yt.js`의 번역 프롬프트에는 이미
> "타임스탬프와 곡목 줄은 그대로 두라"는 규칙이 있다(규칙 6번). 설명란 전체를 넘겼을 때
> 이게 실제로 지켜지는지 **실제 번역을 돌려서 확인**해라. 안 지켜지면 프롬프트를 고쳐라.
>
> **완료 기준:** 12곡 설명란을 넘겨서 일본어로 번역한 실제 결과를 보여줘라.
> 타임스탬프와 곡 제목이 원문 그대로 남아있는지 줄 단위로 대조해서 보고해라.

## 지시문 #07 — 배치 등록

> **작업: 여러 영상에 번역을 한 번에 등록한다. (CS-v1.8)**
>
> 채널 2개 × 주 12곡 운영에서 영상 1편씩 등록하는 건 느리다.
>
> - 영상 여러 개를 선택(체크박스)하고 같은 번역 세트를 한 번에 등록한다.
> - **각 영상마다 미리보기를 먼저 전부 보여주고, 그다음 일괄 적용.** 미리보기 없이
>   바로 실행되는 경로를 만들지 마라.
> - 한 영상이 실패해도 나머지는 계속 진행한다. 실패 사유를 영상별로 표시해라.
>   (`routes/timeline.js`의 `apply-rename`이 이미 이 패턴이다 — 참고해라)
> - 진행률 표시와 **중단 버튼**을 넣어라.
> - 요청 사이에 짧은 간격을 둬라 (기존 번역기의 250ms 패턴 참고).
>
> **주의:** 영상마다 제목·설명이 다르므로 "같은 번역 세트"는 보통 말이 안 된다.
> 실제로 유용한 시나리오는 **영상별로 각각 번역한 결과를 모아서 한꺼번에 등록**하는
> 쪽이다. 구현 전에 어떤 데이터 흐름이 맞는지 나에게 두세 가지 안을 제시하고 물어봐라.
>
> **완료 기준:** 테스트 영상 3개로 실제 배치 등록을 실행하고, 3개 전부의 등록 후
> `localizations` 상태를 읽어서 보여줘라. 일부러 1개를 잘못된 ID로 넣어 부분 실패
> 처리도 확인해라.

## 지시문 #09 — 쿼터 가드 + 등록 이력

> **작업: API 쿼터를 관리하고 등록 이력을 남긴다. (CS-v1.8)**
>
> 유튜브 기본 일일 쿼터는 10,000유닛이고 `videos.update` 1회가 50유닛이다. 배치 등록을

>   방식으로 단순하게 구현해라 (서머타임 때문에 시차 계산은 틀리기 쉽다).

> - 등록 이력을 `.yt-publish-log.json`에 남긴다: 시각, 영상 ID, 언어 코드 목록,
>   **등록 직전의 기존 localizations 전체**(롤백용).
> - `POST /api/yt/undo-publish` — 가장 최근 등록을 되돌린다.
>   `routes/timeline.js`의 `undo-rename` 패턴을 그대로 따라라 (1단계 되돌리기, 부분
>   실패 시 기록 유지).
>
> **완료 기준:** 등록 → 되돌리기를 실제로 실행하고, 되돌린 후 `localizations`가 등록
> 전 상태와 정확히 같은지 대조해서 보여줘라.

# 4. 부록

## 4.1 유튜브 API 쿼터 표

| 호출 | 유닛 | 비고 |
|---|---|---|
| `videos.list` | 1 | 등록 전 읽기 |
| `videos.update` | **50** | 언어를 몇 개 올리든 영상 1편당 50 |
| `playlists.update` | **50** | 재생목록도 동일 |
| `playlistItems.list` | 1 | 내 영상 목록 |
| `channels.list` | 1 | |
| `i18nLanguages.list` | 1 | 12시간 캐시됨 |

기본 일일 한도 **10,000유닛** = 영상 약 190편/일. 주 2편 × 2채널 운영에는 여유가
많지만, 배치 등록에서 실수로 반복 실행하면 소진될 수 있어 #09의 가드가 필요하다.
리셋은 태평양 시간 자정 = 한국 시간 오후 4시(서머타임) / 오후 5시.

## 4.2 주간 운영 루틴 (#07까지 완료 후 기준)

```
1. Suno Weaver Studio에서 곡 세트 생성 → Suno에서 12곡 렌더 → WAV 다운로드
2. Creator Studio 타임라인 도구
   - 폴더 스캔 → 실제 파일명에 연번 적용
   - 괄호 제목 AI 채우기 (한국 채널이면 일본어, 일본 채널이면 한국어)
   - 채널 프로필 선택 → 설명란 완성본 조립
3. [번역기로 보내기] → 채널 프로필의 언어 세트로 번역
4. 영상 업로드 후 → 유튜브 자동 등록 (미리보기 → 등록)
5. 썸네일은 Suno Weaver Studio 쪽에서 (세트 컨텍스트가 이미 연결돼 있음)
```

## 4.3 알아둘 제약

- **OAuth 동의 화면이 "테스트" 상태면 구글이 7일마다 refresh token을 만료시킨다.**
  개인 운영이면 주 1회 재연결로 충분하다. "프로덕션"으로 게시하면 만료되지 않지만
  민감 범위(`youtube.force-ssl`)라 구글 검수가 필요하다.
- **유튜브 언어별 제목은 유튜브가 번역해 주는 기능이 아니다.** 우리가 올린 번역문을
  시청자의 유튜브 언어 설정에 맞춰 보여주는 것뿐이다. 번역 품질은 전적으로 우리 책임이다.
- **KOMCA는 이 파이프라인과 무관하다.** 2025년 3월부터 AI 작곡 음원을 언어 불문 전면
  차단하고 있어 등록 대상이 아니다. 배포는 DistroKid 경로만 쓴다.
